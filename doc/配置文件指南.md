## 目录总览

```
configs/
  config.yaml                 # Hydra 入口（遥操主流程 defaults）
  algorithm/                  # 算法：IK / mapper / runtime
  device/                     # 设备：source / backend / end_effector / paths
  scenes/                     # ★ 声明式场景清单（工坊）
  plugins/                    # 插件默认
  setup/                      # Pico·XRobo 安装用 overrides
  ui/                         # 终端菜单文案与入口
  scene/                      # 双UR 道具/任务/录制（采集仍可读）
    cli.yaml                  # 生成 / 摆放 / 采集的默认参数
    recording.yaml            # MCAP topic + 多相机机位
    props/*.yaml
    tasks/*.yaml
```

根目录下的 `ik/`、`backend/` 等 symlink 只为 Hydra 短写：`ik=ssik`、`backend=mujoco_dual_ur`。

| 目标 | 配置文件 | 关键字段 |
|------|----------|----------|
| 采集是否开窗口、观摩速度 | `scene/cli.yaml` → `collect` | `render`, `pace_s` |
| 采集集数 / 任务 / 臂 | `scene/cli.yaml` → `collect` | `episodes`, `task`, `arm`, `seed` |

| 粘性抓取开关 | `scene/cli.yaml` → `collect` | `sticky_grasp` |

| **相机机位 / 分辨率 / 采样** | `scene/recording.yaml` → `cameras` | `views`, `width`, `height`, `every_n_steps` |
| 第三人称相机位置 | `scene/recording.yaml` | `views` 中 `type: world` 的 `pos` / `lookat` |
| 腕部相机相对夹爪偏移 | `scene/recording.yaml` | `views` 中 `type: site` 的 `offset_xyz` / `lookat_xyz` / `site` |

## 场景采集相关（重点）

### 1. `configs/scene/cli.yaml`

交互菜单「一键：自动化采数据」与 `./start.sh → 场景工坊 / 快捷采集` 共用。

- `collect.recording` → 指向录制配置（默认 `scene/recording.yaml`）
- `collect.camera.enabled` → 仅总开关；机位与 topic **不要**写在这里
- `collect.hold_steps: 0` → 段与段之间不停顿（流畅抓取）
- `collect.pace_s` → 仅影响观摩快慢，不改变轨迹形状

### 2. `configs/scene/recording.yaml`

录制专用：

- `topics`：Foxglove 打开 MCAP 时看到的话题名，可按项目规范改名
- `cameras.views`：默认三路
  - `third_person`：世界系固定第三人称
  - `wrist_left` / `wrist_right`：挂在 `L_g_pinch` / `R_g_pinch`（与 backend 的 prefix + `tcp_site_suffix` 一致）

默认相机话题：

- `/cam/third_person/compressed`
- `/cam/wrist_left/compressed`
- `/cam/wrist_right/compressed`

### 3. `configs/scene/tasks/*.yaml`

定义「做什么」：中英文指令、涉及物体、pick/place/reset stages。  
采集脚本按 `collect.task` 加载对应文件。

### 4. `configs/scene/props/*.yaml`

定义「桌上有什么」：几何、颜色、质量、默认位姿、语义标签。

场景搭建「调用搭建 → 从模型库拉取」默认扫描此目录（见下节）。

### 4.1 `configs/scene/model_library.yaml`

三维模型库入口：

| 字段 | 作用 |
|------|------|
| `default_root` | 默认库目录（相对项目根），现为 `configs/scene/props` |
| `override_root` | 工坊「更换模型库目录」写入的覆盖路径；空=用默认 |
| `extra_roots` | 额外扫描目录列表 |

默认库已含：红色方块、蓝色盘子、绿色方块、黄色圆柱、灰色盒子、白色小球。  
自定义：复制 `props/_template.yaml` 改名，或在工坊内切换到自己的目录。

## 遥操主流程（Hydra）

入口：`configs/config.yaml` → `run_teleop.py` / 菜单「自定义：遥操配置」。

| 分组 | 目录 | 作用 |
|------|------|------|
| runtime | `algorithm/runtime/` | 控制环频率、时长、日志 |
| ik | `algorithm/ik/` | DLS / SSIK / cuRobo |
| mapper | `algorithm/mapper/` | 相对遥操、clutch、腕部姿态 |
| source | `device/source/` | mock / xrobo |
| backend | `device/backend/` | mujoco 仿真 / stub / 真机 |
| end_effector | `device/end_effector/` | gripper / dex_hand |
| paths | `device/paths/` | 资产与输出路径 |

换 Pico 仿真常见组合：

```bash
uv run python run_teleop.py source=xrobo backend=mujoco_dual_ur
```

## 流畅抓取与穿模说明（实现约定）

代码侧约定（一般无需改配置）：

1. **流畅**：`hold_steps=0`，段内 ease-in-out 插值 + 夹爪连续开合，不再在每段末停顿。
2. **视觉一致**：粘性抓取吸附后将方块对齐到 TCP 工具系偏移，并暂时关闭该物体碰撞，避免夹爪「穿过」方块却看起来没夹住。

若仍觉得夹偏/穿模：检查是否为「半合夹持」——应先张开下降再原地闭合；合死会穿模。
机位改 `recording.yaml`；抓取偏移在代码 `DEFAULT_PAD_OFFSET_XYZ ≈ (0,0,-0.021)`（指垫中心，非远端吸附）。

## 物流场景（ArtiXon Arm-6A）

资产与策略在 [`src/teleop_birth/robot/arm/artixon/`](../src/teleop_birth/robot/arm/artixon/)；防穿模 / TACTO 在 [`src/teleop_birth/scene/plugins/`](../src/teleop_birth/scene/plugins/)。通过 `robot.registry` 以 `artixon_arm_6a` 注册。

- 场景清单：[`configs/scenes/logistics_x2arm.yaml`](../configs/scenes/logistics_x2arm.yaml)
- **推荐**：`./start.sh` →「场景工坊」→ 选物流场景 → 遥操或采集
- 快捷：物流 Pico 遥操 / 物流采数据；或 `./start_logistics_teleop.sh`
- 遥操参数：[`configs/robots/artixon_teleop.yaml`](../configs/robots/artixon_teleop.yaml)
- 采集参数：[`configs/robots/artixon_collect.yaml`](../configs/robots/artixon_collect.yaml)
- 入口脚本：`scripts/robots/artixon_{teleop,collect}.py`

采集前：

1. `uv sync --extra collect`（物流触觉再加 `--extra tacto`）
2. `bash scripts/bootstrap_third_party.sh`
3. `./start.sh` → 场景工坊或快捷采集
4. Foxglove 打开 `logs/mcap/artixon/*.mcap`
